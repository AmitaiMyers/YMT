Where should the YMT app live?
Three hosting options

The YMT app (lead research, CRM pipeline and client service hub) is built and running. This brief compares three ways to host it for the team: cheap, medium and expensive. Each option lists the monthly cost, what you get, what you give up, and the first-week steps.

Prices checked November 2026, in US dollars, excluding VAT. Sources are listed at the end. Items marked “est.” are estimates, not quotes.

Option 1 · Cheap: Render Starter

Recommended to start

Render is a managed hosting service: it builds the app from GitHub and runs it, so there are no servers to look after. The app runs as one container with a small permanent disk for the database. This is what the repository is set up for today.

Monthly cost
ItemWhat it isPer month
Web service – Starter512 MB memory, 0.5 CPU, region Frankfurt (EU)$7.00
Persistent disk – 1 GBWhere all company data lives ($0.25 per GB). 1 GB holds years of CRM data.$0.25
Web addressFree …onrender.com address with HTTPS included$0
Total≈ $7.25 (≈ $87 / year)

Render's free plan is not an option: free services sleep when idle and cannot have a disk, so the data would be wiped on every restart.

What you get

  • Live the same day, with no code changes.
  • HTTPS and an installable app on phones and computers.
  • Every push to GitHub updates the app automatically.
  • Data in one place, in the EU, visible on the app's Data & Privacy page.

What you give up

  • Backups are manual (Settings → Data & Privacy → Back up now, then download).
  • Small machine: fine for a handful of users, not for a large team.
  • Updates restart the app, causing under a minute of downtime.
  • No one is on call; Render support is by email.

Week 1: Go live

  1. Open a Render account
    Use a company email and turn on two-factor login.
  2. Create a Web Service from GitHub
    Repository amitaimyers/ymt, runtime Docker, region Frankfurt, plan Starter.
  3. Add a 1 GB disk mounted at /data
    Without the disk, data is lost on every deploy.
  4. Set the environment variables
    ADMIN_USERNAME, ADMIN_PASSWORD (10+ characters), optionally ADMIN_NAME, and HOSTING_LOCATION = “Render, Frankfurt EU”.
  5. Set the start command
    npm run demo:start (creates the admin and demo data on the first start; safe on every restart). For real use without demo data, use node server/src/index.js and create the admin from Render's Shell.
  6. Log in and install the app
    Open the …onrender.com address, log in, and tap Install app on your phone and computer.
Best for: the pilot, demos to partners, and the first months with up to about 10 users.

The same Render setup as Option 1, made dependable for daily use by the whole team. Upgrading from Option 1 is a settings change: same code, same data.

What you get

  • Comfortable for the whole team every day.
  • Daily automatic backups kept outside Render. A disaster costs at most one day of data.
  • A professional web address on your own domain.
  • Alerts when something breaks, and a named person to fix it.
  • Still no code changes; one afternoon of setup on top of Option 1.

What you give up

  • Still one machine: updates cause under a minute of downtime.
  • Data is in the EU, not in Israel. This is fine for most partners; check NDA wording.
  • Login is still username and password (no Microsoft/Google sign-on).
  • Depends on one freelancer's availability.

Week 1: Upgrade from Option 1

  1. Change the plan to Standard and the disk to 5 GB
    In Render: Settings → Instance type, and Disks → Size. Data is kept.
  2. Connect your domain
    Render → Custom Domains, then add the record it shows at your domain provider. HTTPS is set up automatically.
  3. Hire a freelancer for ~4 hours/month
    Their first task is to set up the daily encrypted backup job and test a restore; then a monthly check.
  4. Turn on uptime monitoring
    Point it at /api/health and send alerts to you and the freelancer.
  5. Write a one-page “if it breaks” note
    Who to call, where the backups are, and how to restore. Keep it next to this brief.
Best for: when the team relies on the app every day, roughly 10–40 users, and when clients start asking “where is our data and how is it backed up?”

Option 3 · Expensive: AWS Tel Aviv, enterprise grade

For enterprise clients

Amazon Web Services has a region in Israel (Tel Aviv). This option keeps all data inside Israel, uses a managed high-availability database, and lets staff sign in with company Microsoft or Google accounts. It is a project, not a settings change: the app needs some development work first.

What you get

  • Data stays in Israel. This is the strongest answer for NDA partners and enterprise clients.
  • No downtime during updates; survives a data-center failure.
  • Staff log in with their company account; leavers lose access automatically.
  • Recovery to any moment in the last days or weeks.
  • Formal support with agreed response times, plus a security review you can show clients.

What you give up

  • Roughly 25–50× the monthly cost of Option 1, plus a one-time project.
  • Takes 1–2 months before it is live.
  • More moving parts: it needs the IT partner and can't be run without one.
  • Overkill for a team of under ~40 people unless clients require it.

Getting started (about 1–2 months)

  1. Confirm the trigger
    Do this when a client or partner contract requires data in Israel, company sign-on or an SLA. Get it in writing; it justifies the budget.
  2. Choose an IT partner (AWS-certified, Israel-based)
    Ask for a fixed-price quote for the one-time project and a monthly retainer with response times.
  3. Open a company AWS account
    Owned by the company, not the partner. Turn on billing alerts and two-factor login for the account owner.
  4. Development project
    Move the database from SQLite to PostgreSQL, add Microsoft/Google sign-on, deploy to the Tel Aviv region, and commission a security review.
  5. Migrate and switch over
    Copy the data from Option 1 or 2, test with 2–3 users for a week, then point the domain at AWS.
  6. Install the app on everyone's devices
    Same app, same address; only the login screen changes to “Sign in with Microsoft/Google”.
Note: the costs for this option are planning estimates based on typical AWS list prices and Israeli market rates. Get a real quote before deciding.
Best for: enterprise or government-linked clients, requirements to keep data in Israel, 40+ users, or several offices.
